# Правила работы ИИ-агента над сайтом «Концепция строительства»

Прочитай этот файл целиком перед тем, как начать работу. Он обязателен к исполнению в каждой сессии.

## 1. Что это за проект

- Промо-сайт ООО «Концепция Строительства», Владивосток. Два направления бизнеса на одном сайте:
  - `/metallokonstrukcii/` — металлоконструкции (мангалы, ворота, заборы, навесы, лестницы, тамбуры, теплицы)
  - `/otdelka/` — внутренняя отделка квартир и домов под ключ
  - `index.html` — хаб-главная с общим УТП
  - `/privacy/` — политика конфиденциальности
- Стек: **чистый HTML/CSS/JS**, без сборщиков и фреймворков. Один общий `style.css`, темизация через `theme-init.js` / `theme-toggle.js` (`data-theme` на `<html>`, `localStorage`).
- Хостинг: GitHub Pages (см. `CNAME`, `.nojekyll`). Домен кириллический: `концепция-строительства.рф` = `xn----8sbfkbqbmookekqofldd0ec6lnc.xn--p1ai` (punycode). При добавлении абсолютных URL используй punycode-форму, как уже сделано в meta-тегах и `sitemap.xml`.
- Аналитика: Яндекс.Метрика (id 109981508) + Top.Mail.Ru счётчик — уже установлены в `<head>` каждой страницы, не дублировать.
- Лиды с формы уходят в CRM через Yandex Cloud функцию (`yandex-cloud/submit/`), см. `yandex-cloud/SETUP.md` и `.env.example`. Никогда не коммить реальные токены/ключи — только `.env.example` с плейсхолдерами.
- Репозиторий на GitHub: `felseeker/vlmetal`. Ветка `main`.

## 2. Обязательные навыки (skills) — используй их всегда

Эти навыки установлены **глобально** (`~/.config/opencode/skills/`) и должны активироваться автоматически. Если по какой-то причине агент их не видит — сначала проверь, что версия opencode перезапущена после установки, и явно упомяни навык по имени в первом сообщении.

### UI UX Pro Max (`ui-ux-pro-max`)
Используй для **любых** изменений вёрстки, дизайна, новых секций, лендингов, каталогов услуг.
- Даёт готовые дизайн-системы (цвета, типографику, паттерны) под тип бизнеса — для этого сайта релевантны категории вроде "Home Services", "Local Business", "Construction".
- Перед созданием новой секции/страницы — запусти генератор дизайн-системы, чтобы не придумывать цвета и шрифты на глаз, а обосновать выбор.
- Следуй чек-листу перед сдачей (контраст 4.5:1, focus-состояния, responsive 375/768/1024/1440, никаких emoji вместо иконок, `cursor-pointer` на кликабельных элементах).
- Сайт уже использует тёмную/светлую тему — учитывай обе темы при любых цветовых изменениях (`data-theme="light"` / `[data-theme="dark"]` в `style.css`).

### Motion (`motion`) — анимации
Используй для **любых** анимаций и переходов (hover-эффекты, появление секций, каскадные анимации карточек, hero-карусель, спарки/искры в hero).
- На сайте уже есть кастомные CSS-анимации (`.fade-in`, `hero__sparks`, карусель в hero) — не переизобретай, но при добавлении новых используй навык для best practices и генерации CSS `linear()` spring-кривых вместо магических чисел вроде `ease-in-out`.
- Проверяй `prefers-reduced-motion` — обязательно для доступности.
- Если предлагаешь MotionScore-аудит или премиум-примеры — это требует входа в Motion+ (платно), сначала спроси пользователя, нужно ли это, иначе используй только бесплатную часть (best practices, поиск документации, CSS spring-генерация).

### SEO-чеклист для локального бизнеса (`ai/seo/CHECKLIST.md`)
Кастомный чеклист под этот конкретный сайт — см. файл `ai/seo/CHECKLIST.md` в этой же папке. Обязателен при:
- добавлении/изменении любой страницы (title, description, OG, JSON-LD)
- изменении `sitemap.xml`, `robots.txt`
- добавлении новых изображений (alt-тексты, форматы webp)
- любых изменениях, влияющих на позиции в Яндексе и Google

## 3. Общие правила работы

1. **Не ломай существующую разметку схемы (Schema.org).** В `index.html`, `metallokonstrukcii/index.html`, `otdelka/index.html` есть `LocalBusiness` JSON-LD — при правках синхронизируй данные (адрес, телефон, соцсети) во всех трёх файлах одновременно.
2. **Три HTML-страницы дублируют общие блоки** (header, footer, счётчики метрик, теги в `<head>`). При правке header/footer/counters — правь во всех файлах: `index.html`, `metallokonstrukcii/index.html`, `otdelka/index.html`, `privacy/index.html`, `404.html`.
3. **Изображения:** используй `img/original/` только как источник, финальные изображения в `img/` уже оптимизированы (webp + jpg fallback для hero). Новые фото — сжимай (`sharp` уже есть в зависимостях) и добавляй `width`/`height` атрибуты + `loading="lazy"` (кроме LCP-изображения, у него `fetchpriority="high"`).
4. **CSS:** правь только `style.css` (общий) и `otdelka/otdelka.css` (специфичный для страницы отделки). Версионируй кэш-бастинг `?v=NN` в `<link>` при существенных правках CSS, чтобы обойти кэш GitHub Pages.
5. **Секреты:** реальные токены (Telegram, Yandex Cloud, JWT для CRM) не должны попадать в git. Только `.env.example` с плейсхолдерами. `.gitignore` уже исключает `.env`.
6. **Коммиты:** пиши по-русски, в стиле существующей истории (`git log --oneline`), например: `Добавить страницу внутренней отделки`, `Исправить sitemap и микроразметку`. Не пушь без явного запроса пользователя.
7. **`sitemap.xml`:** при добавлении/удалении страницы — обнови `lastmod` и добавь/убери `<url>`. Не забывай про `robots.txt` (там ссылка на sitemap уже прописана).
8. **Кириллический домен:** всегда используй punycode-форму (`xn----8sbfkbqbmookekqofldd0ec6lnc.xn--p1ai`) в абсолютных URL внутри кода (meta og:url, canonical, JSON-LD, sitemap) — так уже сделано, не переключай на юникод-форму, это ломает совместимость.
9. **Не создавай лишние файлы** — если можно добавить секцию в существующий HTML/CSS, не создавай новый файл. Документацию (`*.md`) создавай только если явно попросили.

## 4. Чего НЕ делать

- Не подключай сборщики/фреймворки (Webpack, React, Tailwind CLI и т.п.) — сайт статический и должен таким остаться (простой деплой на GitHub Pages).
- Не меняй домен/CNAME без явного запроса.
- Не удаляй счётчики аналитики (Яндекс.Метрика, Top.Mail.Ru) без запроса.
- Не отправляй реальные учётные данные в диалог или в коммиты.
- Не используй emoji как иконки в интерфейсе — только SVG (Heroicons/Lucide/кастомные, как уже в проекте).

## 5. Рекомендованные доп. проверки перед сдачей задачи

- [ ] Проверить обе темы (light/dark) — переключатель темы есть в шапке.
- [ ] Проверить мобильную версию (есть `hamburger`-меню).
- [ ] Проверить, что новые/изменённые страницы попали в `sitemap.xml`.
- [ ] Прогнать SEO-чеклист (`ai/seo/CHECKLIST.md`) для изменённых страниц.
- [ ] Если менялась вёрстка — свериться с UI UX Pro Max чек-листом (контраст, фокус, responsive).
- [ ] Если добавлялись анимации — свериться с Motion best practices (`prefers-reduced-motion`, CSS spring вместо ease).
