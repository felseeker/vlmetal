# SEO-чеклист — концепция-строительства.рф

Кастомный чеклист под локальный бизнес во Владивостоке (не общий навык, а инструкция под этот проект). Применяй при любых изменениях контента, вёрстки или структуры сайта.

## Контекст SEO этого сайта

- Ниша: локальные строительные услуги (металлоконструкции + внутренняя отделка), Владивосток и Приморский край.
- Основной поисковик для этой ниши — **Яндекс** (локальный бизнес в РФ), Google — вторично.
- Уже настроено: `sitemap.xml`, `robots.txt`, Яндекс.Вебмастер (verification-мета есть в `<head>`), Яндекс.Метрика, Schema.org `LocalBusiness` с `makesOffer`, OG-теги, Twitter Card.
- Yandex Cloud-функция для приёма лидов (`yandex-cloud/submit/`) — не относится к SEO напрямую, но форма заявки должна оставаться доступной для индексации (не блокировать в robots.txt).

## A. Чек-лист для КАЖДОЙ страницы (title/description/OG)

- [ ] `<title>` уникален для страницы, содержит: услугу + город + УТП, ≤ 60-70 символов.
- [ ] `<meta name="description">` уникален, 150-160 символов, содержит призыв к действию и город.
- [ ] `<meta name="keywords">` — низкий приоритет для Google, но не мешает для Яндекса; не переспамливать (макс 10-15 фраз).
- [ ] `<link rel="canonical">` указывает на punycode-домен, без завершающего дублирования (проверить трейлинг-слэш консистентность).
- [ ] OG-теги (`og:title`, `og:description`, `og:image`, `og:url`) синхронизированы с title/description.
- [ ] `og:image` — реальное фото 1200×630 (сейчас используется `hero-1.jpg` 1600×900, уточнить пропорции при смене).
- [ ] `<meta name="yandex-verification">` не удалять/не менять без явного запроса (это подтверждение сайта в Яндекс.Вебмастере).

## B. Schema.org (JSON-LD)

- [ ] `LocalBusiness` присутствует на главной и обеих страницах-направлениях, данные идентичны (адрес, телефон, geo, openingHours).
- [ ] `makesOffer` перечисляет актуальные услуги с корректными `url`.
- [ ] При добавлении отзывов — рассмотреть `AggregateRating`/`Review` (усиливает сниппет в Яндексе и Google).
- [ ] При добавлении цен на услуги — рассмотреть `Product`/`Offer` с `priceRange` или конкретными ценами (сейчас `priceRange: "OT 5 000₽"` — грамматика проверена намеренно, не "исправлять" на "От", это принятое написание для схемы).
- [ ] Проверять JSON-LD на валидность после правок: https://validator.schema.org/ или Rich Results Test.

## C. Технический SEO

- [ ] Новая страница добавлена в `sitemap.xml` с корректным `priority` (главная — 1.0, направления — 0.9, второстепенные — 0.3) и обновлённым `lastmod` (формат `YYYY-MM-DD`).
- [ ] `robots.txt` не блокирует нужные страницы; если появляются служебные страницы (админка, черновики) — добавить `Disallow`.
- [ ] Изображения: `alt`-текст описательный и с ключевым словом там, где уместно (сейчас в целом хорошо: `"Ворота распашные — металлообработка во Владивостоке"`), избегать спама ключевиками в alt.
- [ ] LCP-изображение (первое в hero) сохраняет `fetchpriority="high"` и `width`/`height`, остальные — `loading="lazy"`.
- [ ] Внутренняя перелинковка: между `index.html`, `/metallokonstrukcii/`, `/otdelka/` должны быть прямые ссылки (сейчас есть через direction-cards и меню) — не терять при рефакторинге.
- [ ] Проверить отсутствие битых ссылок и 404 после структурных изменений (учесть, что URL без `.html` — см. историю коммита "Убрать .html из URL подстраниц").
- [ ] HTTPS уже принудительный на GitHub Pages — не добавлять http-ссылки на свои же страницы.

## D. Локальное SEO (важнее всего для этой ниши)

- [ ] NAP-консистентность (Name, Address, Phone) — везде одинаковый формат телефона (`+7 924 231-04-78` / `+79242310478`), адреса (`ул. Татарская, 11`, Владивосток) во всех местах: сайт, JSON-LD, соцсети (Telegram/WhatsApp/MAX).
- [ ] Профиль в Яндекс.Бизнес / Google Business Profile синхронизирован с данными на сайте (адрес, часы работы, телефон) — если правится адрес/телефон на сайте, напомнить пользователю обновить и в карточках организаций.
- [ ] Гео-таргетированные ключи в контенте: "во Владивостоке", "Приморский край" — использовать естественно, не переспамливать.
- [ ] `openingHoursSpecification` в JSON-LD соответствует реальному графику работы.
- [ ] Ссылки на мессенджеры (Telegram, WhatsApp, MAX) рабочие и попадают в `sameAs` в JSON-LD — это усиливает доверие и связку профилей.

## E. Контент и E-E-A-T (актуально и для Яндекса, и для Google)

- [ ] Отзывы клиентов на странице (если есть секция `#testimonials`) — реальные, с именами/фото где возможно.
- [ ] Портфолио/примеры работ (`img/port-*.jpg`) актуальны и подписаны.
- [ ] Указан год основания / опыт компании (сейчас "8+ лет на рынке", "500+ заказов") — не завышать без подтверждения от владельца.
- [ ] Договор с ООО, гарантия — юридические аргументы доверия — не убирать при редизайне, это ключевой differentiator в нише "гаражных" конкурентов.

## F. После публикации изменений

- [ ] Отправить обновлённый/новый URL на переобход через Яндекс.Вебмастер (Индексирование → Переобход страниц).
- [ ] Проверить страницу в Google Search Console (Проверка URL → Запросить индексирование), если аккаунт подключён.
- [ ] Проверить мобильную версию через Яндекс/Google инструменты проверки на удобство для мобильных.
- [ ] Если менялась разметка `LocalBusiness` — прогнать через Rich Results Test.

## Инструменты, которые можно использовать при наличии MCP/доступа

- `playwright` / `chrome-devtools` MCP — для скриншотов страниц, проверки мобильной адаптивности, аудита производительности (Core Web Vitals: LCP/CLS/INP).
- `webfetch` — для быстрой сверки live-версии сайта после деплоя (концепция-строительства.рф).
